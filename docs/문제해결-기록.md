# 문제 해결 기록

작성일: 2026-11-05
각 항목은 **증상 → 원인 → 해결 → 확인 방법** 순서입니다. 키 값은 어디에도 적지 않았습니다.

## A. 실행·환경

### A1. `vercel dev`가 심볼릭 링크 권한 오류(EPERM)로 실패
- 증상: Windows에서 `vercel dev` 실행 시 EPERM symlink 오류
- 원인: Windows 일반 권한에서는 심볼릭 링크 생성이 막혀 있음
- 해결: 로그인과 링크 권한이 필요 없는 순수 Node 서버 `server.js` 작성 (`/api/chat`, `/api/rates`, 정적 파일). Vercel은 배포할 때만 사용
- 확인: `node server.js` 후 `http://localhost:3000` 동작

### A2. 키 파일 이름 오타, 키가 프로젝트 폴더 안에 있음
- 증상: 키 파일이 `.env,local`(쉼표)로 저장됨. 이후 키 파일이 프로젝트 폴더 안에 생김
- 원인: 파일명 오타, 제출 폴더에 비밀값이 섞일 위험
- 해결: 홈 폴더의 `.exchange_rate.env`로 이동하고 프로젝트 안 사본 삭제. `.gitignore`에 `.env`, `.env.*`, `*.env`, `.exchange_rate.env`, `.vercel`, `node_modules` 추가. `server.js`는 홈 폴더 파일을 먼저 읽음
- 확인: 프로젝트 전체에서 키 형태 문자열 검색 결과 0건

### A3. 코드를 고쳤는데 옛 동작이 그대로
- 증상: 챗봇이 계속 "AI 분석을 불러올 수 없습니다"
- 원인: 수정 전 코드로 떠 있던 `node server.js`가 계속 실행 중
- 해결: 서버 종료 후 재시작
- 확인: 재시작 뒤 정상 응답

## B. AI(Gemini)

### B1. 챗봇 502 `upstream_error`
- 원인: 지정한 모델 `gemini-2.5-flash`, `gemini-2.0-flash`가 더 이상 제공되지 않음(404). 다른 모델은 과부하(503)나 느린 응답
- 해결: 기본 모델을 `gemini-flash-lite-latest`로, 실패 시 `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite` 순으로 자동 전환(환경변수 `GEMINI_MODELS`로 변경 가능). 503/429는 재시도
- 확인: 실제 키로 질문 → 정상 스트리밍

### B2. 잘못된 Gemini 키가 인증 오류로 구분되지 않음
- 원인: Gemini는 잘못된 키에 400 `API_KEY_INVALID`를 줌
- 해결: 이 경우 인증 오류로 처리
- 확인: 일부러 틀린 키로 시험

### B3. 질문 200자 제한이 화면에서만 적용됨
- 원인: 서버가 길이를 검사하지 않음
- 해결: 서버에서 400으로 거부(질문 200자, 대화 기록 8개×1200자, 본문 60,000바이트). 이후 IP당 분당 20회·하루 300회 제한 추가
- 확인: 201자 요청이 400, 제한 초과 시 429와 안내 문구

### B4. AI의 한 줄 해설이 과장되고 시간 기준을 섞음
- 증상: USD가 전일 +0.20원으로 거의 보합인데 "최근 30일 기준… 둘 다 낮아진"이라는 문장이 나옴
- 원인: AI가 "최근 30일"과 "전일 대비"를 섞고, 표현 강도도 매번 달랐음(6번 중 6번 시간 기준 혼용)
- 해결: 문장을 AI가 아니라 코드(`insightSentence()`)가 생성. 표현 임계값은 한 곳(`DAY_STEPS` 하루 0.1/0.5/1%, `PERIOD_STEPS` 30일 0.5/2/4%)에서만 정함. 채팅 AI에는 같은 기준의 크기 라벨을 함께 전달
- 확인: 4가지 시나리오, 전일 없음, 실제 데이터를 별도 계산과 비교, AI 호출 0회

### B5. 답변에 "백분위" 같은 어려운 말
- 해결: 숫자 백분위 대신 "높은 편/중간/낮은 편" 같은 위치 표현(`positionWord`)을 전달하고, 프롬프트에서 용어 사용을 금지
- 확인: 이후 시험 4번에서 0회

### B6. 뉴스 근거 연동 불가
- 증상: 뉴스를 근거로 답하는 기능을 만들고 싶었음
- 원인: 구글 뉴스 RSS는 피드 안에 이용 제한 문구, 네이버는 검색 API 신규 발급이 막힌 것으로 보이고 NAVER API HUB는 유료, 무료 뉴스 API는 지연, 구글 검색 연동은 무료 키로 429
- 해결: 한국은행 지표(코스피, 기준금리, 국고채 3년, 한·미 정책금리)를 AI 도구로 제공. 답변은 "함께 움직인 지표"로 쓰고 **원인 단정은 금지**
- 확인: 실제 지표 값을 ECOS 원본과 대조(예: 2020년 3월 코스피와 금리)
- 정정: 처음에 제안한 구글 뉴스 RSS는 이용 문구를 확인한 뒤 **제가 추천을 철회**함

### B7. 최신 정책금리가 비어 있음
- 원인: 월별 계열이라 최근 월은 발표가 늦음
- 해결: 도구가 400일 전까지 조회하고, 발표된 가장 최근 월을 명시

## C. 한국은행 ECOS 데이터

### C1. 오류가 HTTP 200으로 옴
- 원인: ECOS는 오류도 200 응답 본문의 `RESULT.CODE`로 알림
- 해결: `INFO-100`(인증키 오류)→401, `INFO-200`(데이터 없음)→빈 결과, `ERROR-301` 등은 502로 매핑
- 확인: 일부러 틀린 키와 가짜 서버로 각 경우 시험

### C2. `sample` 키는 10건만 반환
- 원인: 시험용 키는 행 수 제한
- 해결: 서버가 `limited: true`를 응답에 포함하고, 클라이언트는 이 경우 "과거 기록 완료"로 표시하지 않음
- 확인: sample 키 사용 시 완료 처리 안 됨

### C3. ECB에서 한국은행으로 바꿀 때 값이 섞임
- 원인: 이전에 저장된 기록은 ECB 기준이라 한국 시장 값과 다름
- 해결: `migrateSource()`가 합성·수동 입력을 제외한 기존 기록을 삭제하고 소급 상태를 초기화(`data_source: 'ECOS'`, `backfill_v: 3`). 실제 조회로 얻은 기록은 덮어쓰지 않고, 합성·수동 기록은 실제 값으로 교체
- 확인: 전환 후 기록이 모두 ECOS 값

### C4. 오늘 조회한 값이 사실 전날 값
- 증상: 오늘 조회했는데 값이 전날 것
- 원인: ECB 일별 값은 전 영업일 기준
- 해결: 한국은행으로 전환하고, 오늘 기록이 없으면 "오늘 기준값 미발표" 안내
- 확인: 날짜와 시각 표시를 ECOS 원본 날짜와 대조

### C5. 전체 이력을 한 번에 가져오기
- 해결: 5년 단위로 최신부터 나눠 요청하고 한 번에 합쳐 정렬, 초기 이후에는 최근 30일만 보충
- 확인: 13,692건(1977-04-01~) 약 4초. 구간별 0.45~5.6초

## D. 화면

### D1. 차트 말풍선 위치가 틀림
- 원인: SVG 요소에는 `offsetLeft/offsetTop`이 없어 NaN
- 해결: `getBoundingClientRect` 기반으로 계산하고 카드 안으로 제한
- 확인: 여러 점에서 위치 측정

### D2. 모바일에서 화면이 390px보다 넓음(516px)
- 원인: `grid-template-columns: 1fr`와 표의 `min-width`가 칸을 밀어냄
- 해결: `minmax(0,1fr)`, 자식에 `min-width:0`, 표는 가로 스크롤
- 확인: 390px 에뮬레이션에서 가로 넘침 없음 (실제 기기는 미확인)

### D3. 날짜로 이동하면 강조 행이 고정 머리글 아래에 가려짐
- 해결: 강조 행이 상자 중앙에 오도록 `scrollTop`을 계산
- 확인: 이동 후 행이 보이는지 측정

### D4. 표가 60건만 보임
- 해결: 페이지 이동(처음/이전/번호 입력/다음/끝), 건수(25~200), 범위(표시 기간/전체), 날짜 이동

### D5. 상태 배너가 너무 크고 FRESH 문구가 있음
- 해결: 정상 상태는 작은 한 줄 `● 최신값 (기준: …)`, 실패일 때만 큰 배너. 정상 배지(fresh)는 `?dev=1`에서만

### D6. 추가 통화가 달러·엔과 멀리 떨어짐
- 해결: 카드를 같은 격자에 배치, 차트는 접기 방식, 제거/차트 버튼을 알약형 디자인으로 정리(다크 모드 포함)

### D7. 챗봇 창이 긴 답변을 볼 때 같이 내려가거나 튐
- 증상: 긴 답변을 끝까지 보려고 스크롤하면 페이지와 챗봇이 함께 내려감
- 원인 3가지
  1. 답변이 끝나면 입력창에 자동 `focus()`가 걸려 페이지가 474px 스크롤됨
  2. 패널 높이가 화면보다 큼(864px vs 화면 700px)
  3. 답변 영역 끝에서 스크롤이 페이지로 전달됨(1,749px)
- 해결
  - `focus({preventScroll:true})`
  - 데스크톱에서 패널을 flex로 두고 `max-height: calc(100vh - 100px)`, 답변 영역이 남는 높이를 사용
  - `#chat-log { overscroll-behavior: contain; }`
  - 칩 줄은 한 줄 가로 스크롤, 낮은 화면(≤780px)에서는 부제목과 안내를 숨김
  - 모바일에서만 질문 시 `scrollIntoView`
- 확인: 화면 높이 700/800/1000px에서 긴 답변 후 `scrollY`가 0, 패널과 입력창이 모두 보이고 휠이 페이지로 새지 않음. 한계: 긴 답변은 실제 AI가 아니라 **가짜 서버 응답**으로 시험

## E. 작업 방식 중 발생한 실수

### E1. 셸 한 줄 코드로 파일을 고치다 코드가 망가짐
- 증상: `app.js`에 `return ;`, `sl.textContent = ;` 같은 깨진 줄 발생
- 원인: `node -e`와 heredoc에서 백틱(`` ` ``)과 `$`가 셸에 먼저 해석됨
- 해결: Edit 도구로 복구. 이후 수정은 Write로 만든 스크립트나 Edit로만 하고 매번 `node --check`로 문법 검사. 이 원칙을 기억 파일에 기록

### E2. 안전 검사에 걸린 삭제 명령
- 증상: 임시 파일 정리 시 와일드카드(`*.bak`) 삭제가 차단됨 (아무것도 실행되지 않음)
- 해결: 제가 만든 시험 파일만 절대 경로로 하나씩 지정해 삭제

### E3. 확인하지 못한 자료
- `developers.naver.com` 문서는 접속이 막혀 열지 못함 → 검색 결과와 NAVER API HUB 문서로 대신 확인하고, 확인 한계를 그대로 말함

## F. 시험 방법과 그 함정 (앱 버그 아님)

시험은 헤드리스 Chrome을 CDP(WebSocket)로 조작하고, 임시 복사본 프로젝트를 별도 포트(3200/3201/3300)에 띄워, 실제 키로 호출하고, 숫자는 별도 계산으로 다시 검증, 스크린샷으로 육안 확인했습니다.

| 함정 | 해결 |
|---|---|
| 가상 시간 예산이 `requestAnimationFrame`을 멈춤 | 실시간 CDP 스크립트 사용 (`--dump-dom` 대신) |
| 비동기 식을 반환하는 평가 함수가 `{}`를 돌려줌 | 결과를 변수에 담아 별도로 읽음 |
| 잘못된 선택자(`.msg.user:last-of-type`) | 선택자 수정 |
| 평가 문자열 안의 정규식 이스케이프 오류 | 이스케이프 정리 |
| 합성 마우스 이벤트로는 호버가 안 걸림 | `CSS.forcePseudoState`로 호버 상태 강제(실제 마우스 호버는 미확인) |

## G. 아직 해결되지 않았거나 확인하지 못한 것

- Vercel 배포 환경에서의 동작과 30초 제한(`vercel.json`) 실제 확인 못 함
- 요청 제한은 서버리스에서 인스턴스마다 따로 세는 **최선의 방어**
- 한국은행의 호출 제한 오류 코드는 확인 못 함(문구로 추정)
- 추가 통화 차트는 최대 5년
- 실제 휴대폰 확인은 안 함 (390px 에뮬레이션만)
