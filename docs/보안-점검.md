## 2. 발견해서 고친 것

| # | 문제 | 위험 | 수정 |
|---|---|---|---|
| 1 | `server.js`가 모든 네트워크 인터페이스에서 열림 | 같은 와이파이의 다른 기기가 내 컴퓨터 주소로 접속해 **내 키로 챗봇·환율 조회**를 쓸 수 있음 | `127.0.0.1`에서만 열기 |
| 2 | 정적 파일 경로 검사가 `startsWith(PUBLIC)` | `public-evil` 같은 이름의 옆 폴더도 통과할 수 있음. 잘못된 인코딩(`%E0%A4%A`)은 예외 | `PUBLIC + path.sep` 기준으로 검사, NUL 문자 거부, 디코딩 오류는 400 |
| 3 | 보안 헤더 없음 | 다른 사이트가 이 페이지를 프레임에 넣거나, 주입된 스크립트가 외부로 통신할 때 막는 장치가 없음 | `Content-Security-Policy`(자기 출처만 허용, 프레임 금지), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Permissions-Policy`를 `server.js`와 `vercel.json`에 동일하게 적용 |
| 4 | 파비콘 404 | 보안 문제는 아님(콘솔 오류 소음) | 빈 아이콘 지정 |

### 시험 결과
- 응답 헤더 5종 확인
- 경로 탈출 시도 5가지(`/..%2fserver.js`, `/%2e%2e/server.js`, `/../api/chat.js`, `/%00`, 잘못된 인코딩): 403/404/400으로 모두 차단
- 같은 네트워크 주소(`192.168.x.x:3000`)로 접속: 연결 거부
- 보안 헤더 적용 후 실제 브라우저에서 화면, 표(22행), 차트 3개, 다크 모드 전환, 실제 챗봇 답변 모두 정상, 콘솔·CSP 오류 0건

## 3. 남아 있는 한계 (고치지 않았거나 고칠 수 없는 것)

| 항목 | 설명 | 권장 |
|---|---|---|
| `/api/rates` 인증·횟수 제한 없음 | 누구나 호출해 한국은행 호출 한도를 소모할 수 있음. 응답 캐시(10분)가 일부 완화 | 배포 후 사용량 관찰, 필요하면 제한 추가 |
| 챗봇 요청 제한이 최선의 방어 | 서버리스 인스턴스마다 메모리가 따로라 완벽하지 않음. `x-forwarded-for`를 신뢰하는데, Vercel에서는 플랫폼이 설정하지만 다른 환경에서는 조작될 수 있음 | 배포 환경에서만 사용 |
| Gemini 키 한도 | 누군가 반복 호출하면 무료 한도를 소진할 수 있음 | Google AI Studio에서 한도·알림 설정, 키 유출 시 재발급 |
| CSP에 `'unsafe-inline'` 허용 | `index.html`에 테마 초기화 인라인 스크립트가 있고 스타일도 인라인 사용 | 필요하면 해시 방식으로 강화 |
| `.vercel` 폴더 | 프로젝트·조직 식별자가 든 파일이 있음(비밀 키는 아님). `.gitignore`에는 있음 | **제출 압축 시 제외**, 필요 없으면 삭제 |
| `?dev=1` 화면 | 실패 재생·초기화 버튼이 보이지만 브라우저 안의 로컬 저장소만 바꿈 | 서버·데이터에는 영향 없음 |
| 배포 환경 | Vercel에서 헤더와 30초 제한이 실제 적용되는지 확인하지 못함 | 배포 후 응답 헤더 확인 |
| 한국은행 키 | ECOS는 키를 주소 경로에 넣는 방식(제공자 설계). HTTPS이고 로그에 남기지 않음 | 유출 의심 시 재발급 |

## 4. 제출·공유 전 체크리스트
1. 키 형태 문자열 검색 0건 확인
2. 폴더 압축 시 `.vercel`, `node_modules`, 키 파일 제외
3. 개발자 화면(`?dev=1`)에서 "합성 기록 제거" 후 제출
4. 배포 시 `vercel env add GEMINI_API_KEY`, `vercel env add ECOS_API_KEY`로 서버 환경변수에만 설정
5. 채팅·스크린샷·이슈에 키 값을 붙여 넣지 않기. 붙였다면 즉시 재발급
